# カノエのおそうじノート制作

記事本文、黒板画像、Notion公開を一つの制作物として扱う。結論から書き、検索者の疑問を解決しながら、カノエの現場経験が伝わる記事に仕上げる。

## 1. 先に確認するもの

1. 指定されたNotionページを最初に取得し、一次情報、数値、注意事項、現場での説明を抽出する。
2. 既存記事の修正なら、現在のNotion本文と公開ページを再取得してから編集する。
3. 必要に応じて検索意図と競合記事を調べる。技術・安全・メーカー仕様は公式情報を優先する。
4. 数値、料金、改善率、年数、対応メーカーは推測で補わない。情報の日付も確認する。

## 2. SEO設計

- 主キーワードをタイトル、導入、主要見出し、まとめに自然に入れる。
- 検索者が最初に知りたい結論を導入で示す。
- 「原因」「自分でできる対処」「業者に頼む目安」「費用」「修理・買い替え」など、意思決定に必要な順で構成する。
- タイトル、要約、スラッグは重複させず、それぞれの役割を持たせる。
- FAQは本文で解決しきれない具体的な疑問だけに絞る。
- 公式情報とカノエの現場経験を混同しない。現場データには対象範囲、時点、保証ではない旨を添える。

## 3. 読みやすい本文

詳細は [references/writing-and-notion-guide.md](references/writing-and-notion-guide.md) に従う。

- 1文1メッセージを基本にする。
- 1段落は4〜5行以内を目安にする。
- 見出しは読者への問いかけや結論になる自然な日本語にする。
- 専門用語は初出で短く説明する。
- 重要箇所は太字にする。ただし段落全体を太字にせず、結論、判断基準、警告、料金、重要な数値だけを強調する。
- 架空の体験談、件数、改善率、価格を作らない。
- 不安をあおらず、家庭でできる確認から順に案内する。

## 4. 黒板要約画像

`image_gen` で画像を編集する。新規生成ではなく、`assets/chalkboard-shots/shot-2.png` を標準の参照画像に使う。構図上の理由がある場合のみ shot-1、3、4、5 を使う。

### 必須仕様

- 横長のブログ画像。緑の黒板と木枠、紺色の作業着のカノエくんという世界観を保つ。
- 黒板を画面の大部分として、左右・上下をバランスよく広く使う。
- カノエくんは元ショットより小さく、目安として約40%に縮小して下隅に配置する。
- 文字とキャラクターを重ねない。必要なら左右を入れ替える。
- 白いチョーク文字で「短い見出し＋3〜4個の要点」だけを書く。
- 指定外の説明文、英字、アイコン、装飾文字を追加しない。
- 冒頭の「この記事でわかること」用を1枚作る。
- 「参考情報」「参考文献」を除く各H2の直後に、その章の要約画像を1枚ずつ入れる。
- 生成後は、漢字、数字、カンマ、円記号、波線、日付を一枚ずつ目視確認する。誤字があれば使わず再生成する。

プロンプトでは、次を明記する。

```text
画像2を共通ベースとして編集。黒板を画面の大部分として広くバランスよく使う。カノエくんは約40%に縮小して下隅に置き、文字に重ねない。大きな白いチョーク文字で、指定した日本語だけを正確に記載する。指定外の説明、英字、数字、アイコン、装飾文字は追加しない。
```

## 5. Notionへの反映

1. 画像は一時URLではなく、公開ページから継続して参照できるHTTPS URLへ配置する。
2. Notionの添付機能で画像を取り込み、冒頭と各H2直後に配置する。
3. 本文更新後にNotionページを再取得し、見出し、太字、画像数、配置、公開ステータス、スラッグを確認する。
4. 公開サイトのキャッシュ更新を待ち、実ページでタイトル、本文、全画像の読み込み、リンク、コンソールエラーを確認する。

## 6. 完了条件

- Notionの元情報を網羅している。
- SEO設計とnote風の読みやすさが両立している。
- 重要な判断箇所にだけ太字が入っている。
- 冒頭と対象H2直後に黒板画像がある。
- 全画像の文字が正確で、黒板を広く使えている。
- Notionの読み戻しと公開ページの表示確認が終わっている。
- 最終報告を「作業内容」「検証結果」「残タスク」で分ける。
